# G4：前进速度对照

历史实验记录：下文 2 倍面积规则和分开的 A/B 启动步骤属于当时版本。2026-10-09 当前 CPU/NPU 活动入口均已使用固定面积占比 1.2%；请按 [固定面积停车](G4_固定面积停车_20261009.md) 操作。

本次视觉控制配置只把前进请求从 **0.1 m/s 改为 0.3 m/s**。橙色球、无反射场景、模型、检测阈值、偏航规则和停止条件保持相同，继续使用 headless，以同样的显示条件比较。本次仍是 **Mac 仿真身体 + RK3588 板端检测与控制**，不能当作真实机器人演示，也不能凭一次速度对照证明此前表现的根因。

先结束旧会话：在旧终端 **B 按 Ctrl+C**，等板端控制程序退出；再在旧终端 **A 按 Ctrl+C**，等仿真身体退出。保留已有输出。

在 Mac 终端 **A** 启动新的同一球场景：

```zsh
zsh "/Users/ethan/Documents/RK3588 Microduck/work/run_board_runtime_body_camera_ball_no_reflection.zsh"
```

保持 A 运行，再在 Mac 终端 **B** 启动板端控制：

```zsh
zsh "/Users/ethan/Documents/RK3588 Microduck/work/run_board_runtime_robotd.zsh"
```

等待 B 出现 `policy loaded`、`control loop running`，保持 A/B 运行。在 Mac 终端 **C** 只运行这一条：

```zsh
zsh "/Users/ethan/Documents/RK3588 Microduck/work/run_board_follow_ball_cpu_03.zsh"
```

入口先复用原站立与相机联合检查；两项成功后，才以 `--speed 0.3` 运行视觉接近。任一检查失败就停。本次必须使用刚重启的 A/B，不直接重复使用旧身体的一次性起步支撑检查。

视觉运动窗口仍最多 **30 秒**，以 **5 帧**球框面积中位数为基线，达到 **2 倍面积**后锁定停止；本地帧与状态年龄上限仍为 **0.3 秒**，偏航限幅仍为 **±0.2 rad/s**。停止后确认新的 `stand` 状态、零请求及应用命令各轴绝对值小于 **0.01**，持续 **1 秒**。这些条件与上一轮相同；框面积不能换算成准确的真实距离。

等终端 C 回到 Mac 提示符，把**从启动到结束的完整输出**发回来，无论结果是成功、超时还是 error。成功需达到面积条件并完成停止确认；超时或异常退出不算接近成功。如果只是证据回传失败，只补传输出中指定的本次精确目录，不重新运行控制。我们将比较本次与上一轮的运动请求、检测、面积变化和停止记录；MuJoCo 窗口录屏验收仍在此控制验证之后安排。
