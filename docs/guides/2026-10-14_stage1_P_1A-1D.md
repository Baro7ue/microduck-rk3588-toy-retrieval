## Step 2: P, render parity (no robotd, no sim body)

```
scripts/sim/stage1/run_test.zsh parity --floor grid
scripts/sim/stage1/run_test.zsh parity --floor wood
```

Each one renders 10 views (a near and a far arrangement x H0/H1/H2/H3/H1 turned 0.3 rad). The last
line on the screen is the result folder `runs/<UTC>_s1a_parity_<computer name>/`, with
`views_grid.json` (or `views_wood.json`) and 10 PNGs. Then compare with the cloud:

```
scripts/sim/stage1/run_test.zsh parity --compare runs/<the grid folder>/views_grid.json sim/scenes/stage1/parity_cloud/views_grid.json
scripts/sim/stage1/run_test.zsh parity --compare runs/<the wood folder>/views_wood.json sim/scenes/stage1/parity_cloud/views_wood.json
```

It passes when all four edges of every box differ by <= 2 px, and prints `"pass": true`. If it
fails, the Stage 2 training images will be generated on the Mac instead (the fallback in plan 1A).

## Where the results are

Each run has one folder, `runs/<UTC>_s1<a|b|c|d>_s2/`, with the same files as Stage 0:

| File | Content |
|---|---|
| `summary.json` | `verdict` (the conclusion against the plan's acceptance values; `pass` is null for a quick run or a run of only some parts) and `parts` (the numbers of every trial) |
| `truth.csv` | All the Stage 0 columns, plus: `mouth_open` (the beak target, 0 closed, 1 open), `mouth_q` (the beak angle reported to robotd), `holding` (the toy in the beak), and `x/y/z/yaw` of every toy |
| `state.jsonl` | robotd's state every tick (only the skeleton removed; 1D needs `frames.camera`) |
| `events.jsonl` | Every command the script sent and every test-port operation |
| `trials.jsonl` | The time points of every trial; in 1B also the verdict of every closing (error, probability, draw, result) |

After a change to the scoring rules there is no need to run again: `run_test.zsh 1c --rescore runs/<folder>`
rewrites `summary.json` with the new rules.
When a run is done, tell me the folder name. I will read `summary.json`, spot-check `truth.csv` and
compare every item with the acceptance values. Please also confirm that `trials.jsonl` is no longer

## Things to know

- The oracle detection gives boxes only, no positions: for each frame the sim body renders, it also
  renders a segmentation image and derives the box of each toy and the tray, in the same format as
  YOLO's output. The control code has to compute positions from the boxes itself with `ranging.py`,
  from `robot.state` only. The truth is used only for scoring and for placing toys.
- The beak rule (plan 1B): on the tick the beak goes from open (> 0.5) to closed (< 0.5), take the
  nearest toy within 4 cm horizontally and 4.5 cm vertically of the beak tip and draw with
  p = 1 - (e/4 cm)^2. The random seed is fixed at 0, so the same sequence of actions gives the same
  result. Opening the beak while holding, falling (on the ground >= 0.2 s) and a reset all release the toy.
- The beak angle read back: while holding, the angle at which the toy blocks the beak (about +5 deg
  for the bus, +1.7 deg for Henry, +3 deg for the ketchup); an empty beak reads -5 deg. `pick.py`
  uses -1.5 deg as the line between "holding" and "not holding".
- `--oracle-fps`: with `--camera`, A renders 15 frames per second by default (the upstream frame
  rate). On the Mac a frame takes ten-odd milliseconds and does not disturb the simulation; if the
  terminal shows "behind real time", use `--camera --oracle-fps 0` (render only when a test asks for a frame).

| File | What changed | Why |
|---|---|---|
